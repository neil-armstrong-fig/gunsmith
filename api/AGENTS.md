# AGENTS.md: api

The Cloudflare Worker: one Worker serves the site (static assets) and `/api/*` from the same origin, so there is no CORS and the
session cookie will be same-site. Root `AGENTS.md` still applies. The design is `docs/match-netcode.md` (rooms, the tick, fog) and
`docs/ai-hosting.md` (the AI pipeline runs inside this Worker). Modelled on janggi's `api/`.

## Import boundaries

`api/` may import `@gunsmith/shared`, `@gunsmith/engine` and `@gunsmith/ai` (`eslint.config.js`). **Nothing imports it**: the webapp
and the acceptance specs reach it over HTTP and WebSocket, so a frame's shape is written out on both sides (`webapp/src/online/types/`).
Import with the `@src/*` alias.

## What is here

- **The model: plain functions and singletons, reached by import (the user's rule, 2026-11-19; janggi's).** Nothing is passed down a request as a bag of services, and no function takes the Worker's `env`. A route reads a binding or a secret from `workerEnvironment` (`env/WorkerEnvironment`, the one file that imports `cloudflare:workers`) **where it is used**, never copying it into a constant, and calls the plain function it needs (`findOrCreateAccount`, `googleSubjectOf`, `runWeaponPipeline`). Pure helpers keep their values as arguments (`isTrustedOrigin(origin, settings)`, `returnAddress(asked, settings)`) and the caller passes `workerEnvironment`. `ApiWorker.ts` is the runtime's front door and, with `durable-objects/match/Match.ts`, the only code that touches the Workers runtime beyond that import: keep them to wiring, not unit tested.
- **`router/` is the front door's dispatch, one folder per route (2026-11-19).** `router/HandleApiRequest.ts` only matches the path and hands the request to the route that owns it, in `router/routes/<name>/`: `rooms/` (`POST /api/rooms`, a friend code), `socket/` (a WebSocket upgrade on `/api/rooms/<code>/socket`, handed to that room's `Match` Durable Object), `weapons/` and `arenas/` (the generation routes, below), `me/`, `sign-in/` and `log-out/` (sign-in, below), and `shared/` for what two routes use (`ReserveCredit` with its `session/`, `prompt-request/` and `types/`; `origin/`; `friend-code/`; `time-limit/`; the test-only `fake-ledgers/` and `fake-accounts/`). A new route is a new folder beside these with its own handler, `types/`, tests and (if it has them) `property-tests/`, plus one branch in `HandleApiRequest.ts`; a helper two routes need goes in `shared/`, one route's helper beneath that route. `router/origin-check/` turns away a forged request before any route sees it. The Durable Objects are not routes and live in `durable-objects/` (next bullet).
- **`durable-objects/` holds the three Durable Object domains (2026-11-19):** `match/` (a room's match), `credit-ledger/` (one `CreditLedger` per account) and `spend-ledger/` (the one global `SpendLedger`), each a folder with its one wiring root file, the plain classes beneath it and its tests; `shared/utc/` is what the two ledgers share. `ApiWorker.ts` exports them (`wrangler.jsonc` names the classes) and no route imports them: a route reaches one through the `env` namespace (`MATCHES`, `CREDITS`, `SPEND`), so renaming a class or folder never touches a route. A new Durable Object is a new folder beside these.
- `durable-objects/match/room/MatchRoom.ts` is the match as plain state, no network: seats, what each seat last asked for, the engine's world, the tick. `match/Match.ts` only feeds it frames and a clock and sends what it answers. `match/messages/` parses what a client sends (`unknown` until parsed; the engine then caps what an input may ask for): an `input` frame (`ParseInputMessage`) or a `ready` frame (`ParseReadyMessage`).
- **Rounds and the match are the room's.** A room's world carries a best of three (`startMatch`), which `playStep` scores as each round ends. A decided round freezes until **both seats send `ready`**; then `MatchRoom` begins the next round (`nextRound`: the score kept, both fighters restored to their starting places) or, once the match is decided, a fresh match. A `ready` while the round is still being fought is ignored, so a seat cannot ask ahead. Each snapshot also carries `ready {player, opponent}` (who has asked, from that seat's side); it is only flags, so it tells nothing about where anyone is. There is no ring and no pickup in a room yet.
- **A seat is kept for its person (reconnect, 2026-11-18).** Each seat is given a secret `token` in the `joined` frame (sent once on **every** connection); a browser shows it as `?token=` on the socket URL to get the same seat back (`MatchRoom.reconnect`). Before the match begins a seat that leaves is simply given back (its token is void); after it, `leave` freezes the fighter (its ask is zeroed; it stays in the world and hittable) and the seat waits for the reconnect window (below). A token that is not a seat's is an ordinary newcomer's: with both seats held the socket is closed `4409 room-full`. If the seat's old connection is still open when the token arrives it is closed `4410 replaced`. Both codes mean "do not come back" to the browser. Rebinding **forgets what the seat had reached** (`ack`, its held input): a returning page counts its inputs from zero again, and an old `ack` would make the server drop every one of them as stale. `Match` ignores frames and closes from a socket that no longer holds the seat, so a late `close` cannot freeze the seat's new connection. If both players are away the Durable Object may be evicted and the room's state lost (a known limit).
- **The room does not wait for ever (2026-11-18).** Each seat has a clock of how long it has been silent, counted in the game time `MatchRoom.tick` plays (no wall clock in `MatchRoom`), and checked **one step at a time** so that of two seats running out in one stretch the first is the one that forfeits. It restarts when the seat's person leaves or comes back, **asks for something new** (`forfeit/AskChanged`: the browser's own rule, so the heartbeat repeating the same ask does not count), clicks "Next round", and for both seats when a round is decided or begins. A seat whose person is away may be silent 30 s (`reconnectSeconds`), one who is there 60 s (`idleSeconds`; `DefaultForfeitLimits`). Then it **forfeits**: a round being fought goes to the other seat (the engine's `match/ForfeitRound`, scored with its `scoreRound`, so two forfeits lose the match as two lost rounds do); a decided round that was waiting for this seat to click has the _next_ round forfeited as it begins, leaving the other seat the usual "Next round"; a decided match forfeits nothing. **Both seats running out together forfeit nothing** (two people gone is a stall, not a win). The clock stops with the last connection (`Match` clears its interval), so a room everyone has left does not run down. Specs shorten the limits with `?reconnectSeconds=` and `?idleSeconds=` on the page address: the webapp passes them on the socket URL, `Match` reads them from the room's **first** connection only (`forfeit-limits/ParseForfeitLimits`: never longer than the real limits, never under a second, non-numbers ignored).
- **`routes/weapons/` and `routes/arenas/` are the two generation routes (weapon 2026-11-18, arena 2026-11-19).** `POST /api/weapons` (`weapons/GenerateWeaponRoute`) and `POST /api/arenas` (`arenas/GenerateArenaRoute`) take `{prompt}` from a signed-in player: the **session cookie** names the account that pays (`routes/shared/session/AccountOfRequest`; the `X-Account-Id` header is gone and nothing reads it). The guards are shared (`routes/shared/ReserveCredit`), in order, each taking nothing: method (405), a pipeline to run (503 `ai-unavailable`), a signed-in player (401 `account-required`), body (`routes/shared/prompt-request/ParsePromptRequest`, 400), `SPEND.status()` (503 `ai-off` with `returnsAt`), then `CREDITS.reserve(key, kind)` (402 `no-credits`) **before** the pipeline runs and, when the route passes an estimate (`reservedMicrodollars`: `WEAPON_SPEND` for the weapon route, `ARENA_SPEND` for the arena route), `SPEND.reserve(key, reservedMicrodollars)` after it (credit first, so an account with none never touches the one global ledger; a `paused` spend refunds the credit and answers 503 `ai-off` with `returnsAt`; both routes pass one: `WEAPON_SPEND` and `ARENA_SPEND`); the key is a fresh `crypto.randomUUID()` per request. Each route then runs its pipeline and settles. **Weapon:** `created` settles `weapon` (1 credit), `rejected` settles `rejected` (half), `invalid` or a throw refunds; the spend settles at the model calls the outcome made (`durable-objects/spend-ledger/estimate/weapon/SettledWeaponSpend`), or in full on a throw (its calls may have been billed). **Arena:** `created` settles `arena` (1), `rejected` settles `rejected` (half), `builtIn` (the model's arena was unusable, so a built-in one is given) **refunds the credit and still answers the arena** (`{status: "builtIn", arena, reason}`), and a throw refunds; the spend settles at the calls the outcome made (`estimate/arena/SettledArenaSpend`: moderation, then generation, then the one repair, each at its own price), **built-in arenas included since the model was billed**, or in full on a throw; both routes refund the credit and settle the full spend reservation on a throw (502 `generation-failed`) or a timeout (504 `generation-timed-out`). The shared deadline (`routes/shared/time-limit/`) is 30 s. A pipeline may still finish after the response, and late results have no ledger effect. Each route imports its pipeline from its own `pipeline/` folder (`routes/weapons/pipeline/` and `routes/arenas/pipeline/`: `IsWeaponPipelineAvailable` and `RunWeaponPipeline`, and the arena pair; `@gunsmith/ai`'s `generateWeapon` / `generateArena` with their models once the Worker has them). **Both are stubs until a production adapter is wired** (availability says no, so both answer `ai-unavailable`: no credit, no spend); tests mock the two modules. **Sign-in has landed (2026-11-19), so the "no production smith before a verified account" rule is met; wiring one still needs ai's adapters and the user's authorisation for paid calls.** Provider cancellation remains open. `ArenaOutcome.arena` is still `unknown` (ai's draft; the answer drops `nodes`, `modelCalls` and `refunded`). Tests use `routes/shared/fake-ledgers/FakeLedgers` (budget's real `CreditAccount` behind a fake namespace, recording each call as `reserve:<kind>` so a wrong kind shows even while prices are equal) and each route's `property-tests/` (`pnpm test:properties`).
- **`routes/credits/` is the balance read (budget, 2026-11-19).** `GET /api/credits` from a signed-in player (`CreditStatusRoute`) answers `{balance, dailyAllowance, prices, aiOn, returnsAt?}` from `CREDITS.balance()`, `SPEND.status()`, `CREDIT_PRICES` and `DAILY_CREDITS`. Read-only: it never reserves, settles or refunds (`property-tests/` holds that for any run of reads). 405 `Allow: GET`, 401 without a session.
- **Sign-in is Google OIDC with PKCE and D1 sessions (2026-11-19; `docs/sign-in.md`).** `GET /api/auth/google?return=` (`routes/sign-in/start/`) keeps a random `state`, a PKCE verifier and the **whole-origin-checked** return address in a short `HttpOnly` cookie and redirects to Google; `GET /api/auth/google/callback` (`sign-in/finish/`) compares the state, exchanges the code, finds or makes the account (id = a fresh `crypto.randomUUID()`, never Google's `sub`; no email or name is stored, the display name is two generated words) and starts a **session**: a 256-bit token in an `HttpOnly; Secure; SameSite=Lax` cookie for 30 days, of which D1 keeps only `sha256(token)`. **Every failure redirects back signed out** (one closed-event `console.warn`, never a code, state, subject, address or cookie); `POST /api/auth/logout` ends the one session and succeeds with none; `GET /api/me` is always 200 `{signedIn, displayName?}` and never touches D1 without a cookie. `LOGIN_LIMITER` (10 a minute per address) fails open. With no `GOOGLE_OAUTH_CLIENT_ID`/`_SECRET` every attempt returns signed out, so guests, rooms and acceptance need none. **`DELETE /api/account` waits on budget's `CreditLedger` delete.** **Layering (ESLint enforces it):** Drizzle and D1 live in `src/accounts/` alone (**one plain function per operation, each in its own folder with its unit test beside it**: `find-or-create-account/`, `create-session/`, `account-of-session/`, `delete-session/`, `remove-account/`; the one root file is `Database.ts`, whose `database()` opens `workerEnvironment.DB` per call; `schema/`, `types/`, and `testing/` grouped as `in-memory/`, `local-database/`, `contract/`), `oauth4webapi` in `src/sign-in/` alone (`GoogleAuthorizationUrl`, `GoogleSubjectOf`, `IsGoogleConfigured`), and `cloudflare:workers` only in `env/WorkerEnvironment` (the Durable Object classes extend its `DurableObject`). **Tests:** `src/testing/SetupApiTests.ts` runs before every test file and `vi.mock`s what is outside the process (the five account functions onto `accounts/testing/in-memory/TestAccounts`, in memory; the two Google functions onto `sign-in/testing/TestGoogle`; the four pipeline modules, automocked and defaulting to available), resets those fakes and **clears every key of `workerEnvironment` after each test**, so a test sets the bindings it needs (`workerEnvironment.CREDITS = ...`, `fakeLedgers()` does it for the ledgers) and nothing leaks. **Each function's own test runs the real function on real local D1** (`testing/local-database/UseLocalDatabase`: wrangler's `getPlatformProxy` in plain node, migrations applied, an empty database per test set as `workerEnvironment.DB`; the test arranges and asserts with raw SQL so it exercises that function alone, and `vi.unmock`s it). `testing/contract/AccountsContract` is the parity check: the same cases run on the in-memory functions (`testing/in-memory/InMemoryAccounts.test.ts`) and on the five real ones together (`testing/contract/RealAccounts.test.ts`). A test of a mocked function itself calls `vi.unmock` for it. SQL is `migrations/` (`pnpm db:generate -- --name=<change>`, read it, then **Wrangler applies it**: `pnpm db:migrate:local`, never `drizzle-kit migrate`/`push`; Prettier ignores the folder). **Until release there is one migration (the user's rule, 2026-11-19):** when the schema changes, delete `migrations/` and generate it again (`pnpm db:generate -- --name=<what the schema is>`) rather than adding `0001_…`, then delete the local D1 (`.wrangler/state/v3/d1`) and `pnpm db:migrate:local`; the local database is disposable. Separate migration files start at release, when a real database exists to migrate.
- **A request is checked for its origin before any route (`router/origin-check/IsForgedRequest`).** A `POST`/`PUT`/`PATCH`/`DELETE` or a WebSocket upgrade whose `Origin` is not trusted (a missing one included) answers 403 `forbidden-origin`; reads and the OAuth callback are not asked. Trusted means the whole origin is in `ALLOWED_ORIGINS` (`wrangler.jsonc`: the site) or, only when `ALLOW_LOOPBACK_ORIGINS` is `"true"`, a plain-http localhost/127.0.0.1 page at **any port**. That flag is passed **only by the start scripts** (`pnpm start`'s `--var`, the managed acceptance Worker in `PreviewServers.ts`), never declared in `wrangler.jsonc` or `infra/`, so a deployed Worker cannot have it. Any new local way to start the Worker for a browser needs the flag.
- `durable-objects/credit-ledger/` and `spend-ledger/` are budget's: AI credits and spend (`docs/cost-and-budget.md`). Each domain has one root file, a Durable Object (`credit-ledger/CreditLedger.ts`, one per account; `spend-ledger/SpendLedger.ts`, the one global), that only wires; the decisions are plain **synchronous** classes beneath it (`credit-ledger/account/CreditAccount.ts`, `spend-ledger/meter/SpendMeter.ts`). Keep them synchronous: the object runs one request at a time, so no `await` between a read and its write is what makes a reserve atomic. Time is passed in as a parameter (only the Durable Object reads the clock). `shared/utc/UtcDay.ts` is shared by both. `spend-ledger/estimate/` holds one folder per route: `weapon/` (the tunable `WEAPON_SPEND`, a worst-case reserve and a per-call price, and `SettledWeaponSpend`) and `arena/` (`ARENA_SPEND`, a price for each call by its place, and `SettledArenaSpend`), each an estimate from the outcome's `modelCalls`, since neither outcome reports the tokens of its stats or arena calls. `SpendLedger.alarm()` emails the 50/80/100% budget alerts through the `ALERT_MAIL` `send_email` binding (`spend-ledger/alerts/`: `SendDueAlerts` marks an alert sent only after its email has gone, so a failure is retried; `email/DeliverAlertEmail` is the untested `cloudflare:email` edge, with its pure builder beneath it; the 100% alert is due once a request is refused for crossing the monthly cap, since spend then stops short of it); `ALERT_TO_ADDRESS` is a secret and, unset, nothing is sent. `CreditLedger.erase()` (the one method that awaits: a single `deleteAll`) is what `DELETE /api/account` calls last, after the D1 rows are gone; the fake ledgers' stub records `erase` and drops that account.
- **Fog is the engine's** (`@gunsmith/engine/seat/ViewOfSeat`): the server sends each seat exactly `viewOfSeat(world, seat)`, so a hidden fighter is absent from the frame. Never build a snapshot another way. `TwoBrowsersHidingFromEachOther` reads the received frames to prove it.
- The arena is engine's Duel (`@gunsmith/engine/built-in-arenas/DuelBuiltInArena`) until arenas come from rooms.

## Conventions

- **Decide in plain functions and plain classes; keep the runtime at the edge.** A class is for state (`MatchRoom`) or the Durable Object itself.
- Property tests (`fast-check`, `durable-objects/match/property-tests/**/*Invariants.test.ts`: the room's in `match-room/` with its arbitraries, `step-checks/` and `score-checks/` beneath it, the parser's beside it) are left out of `pnpm checks` and run with `pnpm test:properties`, as the engine's do.
- Tests run in plain node (`vitest.config.ts`): `@cloudflare/vitest-pool-workers` peers on vitest 4 and the workspace is on 5. A route takes a `Request`; a test sets what it reads on `workerEnvironment` (a fake `MATCHES` namespace, a limiter) and `SetupApiTests` empties it afterwards.
- Pacing is `durable-objects/match/tick/MatchTick.ts`: a clock 30 times a second plays the engine's 1/60 s steps that real time owes (`StepsOwed`, so a late timer does not slow the game) and sends a snapshot after each. The browser predicts its own fighter and blends the other between snapshots (`webapp/src/online/`), so 30 is enough; at 20 the plain local-feeling game was choppy only because nothing smoothed it. The wire carries `seq` on each input and `ack` (`seq`, `held`) on each snapshot (`@gunsmith/shared/online/types/InputAck`) so the browser knows which of its inputs the server has played.
- Not built yet, on purpose: `DELETE /api/account`, the account library and its limits, the matchmaker, the closing ring and pickup in a room, an "opponent is away" notice for the player who stays, spectators, rate limiting beyond sign-in, recordings. Add each when a spec needs it.

## Running

```bash
pnpm --filter @gunsmith/api db:migrate:local   # once, and after each new migration: the local D1 (`.wrangler/state`); sign-in needs it, guests do not
pnpm api:dev                 # the Worker on :8787 (API_PORT=8790 pnpm api:dev for another port); trusts localhost pages at any port
pnpm start                   # the webapp; its /api proxy (with WebSockets) points at :8787, or at API_URL
```

For an acceptance run, serve the build with `API_URL=http://localhost:<worker port> pnpm --filter @gunsmith/webapp exec vite preview --port <port> --strictPort`, and point `WEBAPP_URL` at it. Use your own ports and stop only your own servers. For the real Google flow keep `GOOGLE_OAUTH_CLIENT_ID` and `GOOGLE_OAUTH_CLIENT_SECRET` in the one git-ignored `.env.local` at the project root: `pnpm api:dev` passes it to Wrangler with `--env-file` when it exists (no `api/.dev.vars`, which would take precedence), and sets `GOOGLE_REDIRECT_URI` itself from the port (`http://localhost:<port>/api/auth/google/callback`, which must be registered with the OAuth client). Everything in that file becomes a local binding, so keep it to local values. Agents never read it.
