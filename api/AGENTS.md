# AGENTS.md: api

The Cloudflare API Worker serves `/api/*` at `gunsmith-api.neilarmstrong.dev`. It allows credentialed HTTP requests from the webapp’s exact origin at `gunsmith.neilarmstrong.dev`. Root `AGENTS.md` still applies. The design is `docs/match-netcode.md` (rooms, the tick, fog) and
`docs/ai-hosting.md` (the AI pipeline runs inside this Worker). Modelled on janggi's `api/`.

## Import boundaries

`api/` may import `@gunsmith/shared`, `@gunsmith/engine` and `@gunsmith/ai` (`eslint.config.js`). **Nothing imports it**: the webapp
and the acceptance specs reach it over HTTP and WebSocket, so a frame's shape is written out on both sides (`webapp/src/online/types/`).
Import with the `@src/*` alias.

## What is here

- **The model: plain functions and singletons, reached by import (the user's rule, 2026-11-19; janggi's).** Nothing is passed down a request as a bag of services, and no function takes the Worker's `env`. A route reads a binding or a secret from `workerEnvironment` (`env/WorkerEnvironment`, the one file that imports `cloudflare:workers`) **where it is used**, never copying it into a constant, and calls the plain function it needs (`findOrCreateAccount`, `googleSubjectOf`, `runWeaponPipeline`). Pure helpers keep their values as arguments (`isTrustedOrigin(origin, settings)`, `returnAddress(asked, settings)`) and the caller passes `workerEnvironment`. `ApiWorker.ts` is the runtime's front door and, with `durable-objects/match/Match.ts`, the only code that touches the Workers runtime beyond that import: keep them to wiring, not unit tested.
- **`router/` is the front door's dispatch, one folder per route (2026-11-19).** `router/HandleApiRequest.ts` only matches the path and hands the request to the route that owns it, in `router/routes/<name>/`: `rooms/` (`POST /api/rooms`, a friend code), `socket/` (a WebSocket upgrade on `/api/rooms/<code>/socket`, handed to that room's `Match` Durable Object), `weapons/` and `arenas/` (the generation routes, below), `me/`, `sign-in/`, `log-out/` and `account/` (sign-in, below), and `shared/` for what two routes use (`ReserveCredit` with its `session/`, `prompt-request/` and `types/`; `origin/`; `time-limit/`; the test-only `fake-ledgers/` and `fake-accounts/`). A new route is a new folder beside these with its own handler, `types/`, tests and (if it has them) `property-tests/`, plus one branch in `HandleApiRequest.ts`; a helper two routes need goes in `shared/`, one route's helper beneath that route. The room generator uses the friend-code format from `@gunsmith/shared/online/friend-code`, and the socket route uses its canonical validator. `router/origin-check/` turns away a forged request before any route sees it. The Durable Objects are not routes and live in `durable-objects/` (next bullet).
- **`durable-objects/` holds the three Durable Object domains (2026-11-19):** `match/` (a room's match), `credit-ledger/` (one `CreditLedger` per account) and `spend-ledger/` (the one global `SpendLedger`), each a folder with its one wiring root file, the plain classes beneath it and its tests; `shared/utc/` is what the two ledgers share. `ApiWorker.ts` exports them (`wrangler.jsonc` names the classes) and no route imports them: a route reaches one through the `env` namespace (`MATCHES`, `CREDITS`, `SPEND`), so renaming a class or folder never touches a route. A new Durable Object is a new folder beside these.
- `durable-objects/match/room/MatchRoom.ts` is the match as plain state, no network: seats, what each seat last asked for, the engine's world, the tick. `match/Match.ts` only feeds it frames and a clock and sends what it answers. `match/messages/` parses what a client sends (`unknown` until parsed; the engine then caps what an input may ask for): an `input` frame (`ParseInputMessage`), a `ready` frame (`ParseReadyMessage`) or a pre-round action (`ParsePreRoundMessage`, below).
- **Rounds and the match are the room's.** A room's world carries a best of three (`startMatch`), which `playStep` scores as each round ends. A decided round freezes until **both seats send `ready`**; then `MatchRoom` begins the next round (`nextRound`: the score kept, both fighters restored to their starting places) or, once the match is decided, a fresh match. A `ready` while the round is still being fought is ignored, so a seat cannot ask ahead. **Each round starts on the engine's fair start** (`fairStart(arena, seed)`, a seed drawn per round by the room's `makeSeed`, third constructor argument, random unless the page pins one): the two fighters stand on a matching pair of places, facing the middle, never on fixed tiles. The room's first connection may pin the seed with `?startSeed=` (`start-seed/ParseStartSeed`, a whole number; the webapp passes it on and the acceptance DSL's `addressOfRoom` always sets one), so every round of that room starts on the same pair. Each snapshot also carries `ready {player, opponent}` (who has asked, from that seat's side); it is only flags, so it tells nothing about where anyone is. **Each round also has the closing ring and a submachine gun lying in the arena (2026-11-20, engine)**: `worldOfRound` draws both from the round's one seed with the engine's `startRing` and `startPickup` (each on its own stream, from both starting places, so the weapon lies as near as can be to equally far from the two seats by the way they would walk), and the ring starts again with every round. The ring is told to both seats; the weapon only to a seat that sees it (`viewOfSeat`), and the other seat hears it taken as a direction and a loudness. The room's first connection may bring the ring sooner or faster with `?ringDelay=` and `?ringClosing=` (`ring-timing/ParseRingTiming`: never later or slower than the real 45 s and 30 s, so a page cannot switch it off for the other player; the webapp passes them on and `addressOfRoom` shows them only when a spec asks), and `MatchRoomOptions.ringTiming` sets it directly for a test. A room test about two idle seats gives them a ring that never closes (`A_RING_THAT_NEVER_CLOSES`), or the real one ends their round after 75 s.
- **A seat is kept for its person (reconnect, 2026-11-18).** Each seat is given a secret `token` in the `joined` frame (sent once on **every** connection); a browser shows it as `?token=` on the socket URL to get the same seat back (`MatchRoom.reconnect`). Before the match begins a seat that leaves is simply given back (its token is void); after it, `leave` freezes the fighter (its ask is zeroed; it stays in the world and hittable) and the seat waits for the reconnect window (below). A token that is not a seat's is an ordinary newcomer's: with both seats held the socket is closed `4409 room-full`. If the seat's old connection is still open when the token arrives it is closed `4410 replaced`. Both codes mean "do not come back" to the browser. Rebinding **forgets what the seat had reached** (`ack`, its held input): a returning page counts its inputs from zero again, and an old `ack` would make the server drop every one of them as stale. `Match` ignores frames and closes from a socket that no longer holds the seat, so a late `close` cannot freeze the seat's new connection. If both players are away the Durable Object may be evicted and the room's state lost (a known limit).
- **The room does not wait for ever (2026-11-18).** Each seat has a clock of how long it has been silent, counted in the game time `MatchRoom.tick` plays (no wall clock in `MatchRoom`), and checked **one step at a time** so that of two seats running out in one stretch the first is the one that forfeits. It restarts when the seat's person leaves or comes back, **asks for something new** (`forfeit/AskChanged`: the browser's own rule, so the heartbeat repeating the same ask does not count), clicks "Next round", and for both seats when a round is decided or begins. A seat whose person is away may be silent 30 s (`reconnectSeconds`), one who is there 60 s (`idleSeconds`; `DefaultForfeitLimits`). Then it **forfeits**: a round being fought goes to the other seat (the engine's `match/ForfeitRound`, scored with its `scoreRound`, so two forfeits lose the match as two lost rounds do); a decided round that was waiting for this seat to click has the _next_ round forfeited as it begins, leaving the other seat the usual "Next round"; a decided match forfeits nothing. **Both seats running out together forfeit nothing** (two people gone is a stall, not a win). The clock stops with the last connection (`Match` clears its interval), so a room everyone has left does not run down. Specs shorten the limits with `?reconnectSeconds=` and `?idleSeconds=` on the page address: the webapp passes them on the socket URL, `Match` reads them from the room's **first** connection only (`forfeit-limits/ParseForfeitLimits`: never longer than the real limits, never under a second, non-numbers ignored).
- **`routes/weapons/` and `routes/arenas/` are the two generation routes (weapon 2026-11-18, arena 2026-11-19).** `POST /api/weapons` (`weapons/GenerateWeaponRoute`) and `POST /api/arenas` (`arenas/GenerateArenaRoute`) take `{prompt}` from a signed-in player: the **session cookie** names the account that pays (`routes/shared/session/AccountOfRequest`; the `X-Account-Id` header is gone and nothing reads it). The guards are shared (`routes/shared/ReserveCredit`), in order, each taking nothing: method (405), a pipeline to run (503 `ai-unavailable`), a signed-in player (401 `account-required`), body (`routes/shared/prompt-request/ParsePromptRequest`, 400), `SPEND.status()` (503 `ai-off` with `returnsAt`), then `CREDITS.reserve(key, kind)` (402 `no-credits`) **before** the pipeline runs and, when the route passes an estimate (`reservedMicrodollars`: `WEAPON_SPEND` for the weapon route, `ARENA_SPEND` for the arena route), `SPEND.reserve(key, reservedMicrodollars)` after it (credit first, so an account with none never touches the one global ledger; a `paused` spend refunds the credit and answers 503 `ai-off` with `returnsAt`; both routes pass one: `WEAPON_SPEND` and `ARENA_SPEND`); the key is a fresh `crypto.randomUUID()` per request. Each route then runs its pipeline and settles. **Weapon:** `created` settles `weapon` (1 credit), `rejected` settles `rejected` (half) **unless it was turned away before any model call (`modelCalls` 0, the length pre-check), which refunds**, `invalid` settles `unusable` (half: three calls were billed), a throw refunds; the spend settles at the tokens the outcome's `usage` reports, priced at Haiku's rates (`durable-objects/spend-ledger/estimate/weapon/SettledWeaponSpend`, falling back to the model calls it made at a price each when no usage was reported), or in full on a throw (its calls may have been billed). **Arena:** `created` settles `arena` (1), `rejected` settles `rejected` (half), `builtIn` (the model's arena was unusable, so a built-in one is given) **settles `unusable` (half a credit) and still answers the arena** (`{status: "builtIn", arena, reason}`), `outcome.refunded` (ai sets it exactly when no model was called, the length pre-check) refunds, and a throw refunds; the spend settles at the tokens the outcome's `usage` reports (`estimate/arena/SettledArenaSpend`; with none reported, the calls it made, moderation, then generation, then the one repair, each at its own price), **built-in arenas included since the model was billed**, or in full on a throw; both routes refund the credit and settle the full spend reservation on a throw (502 `generation-failed`) or a timeout (504 `generation-timed-out`). The shared deadline (`routes/shared/time-limit/`) is 30 s. A pipeline may still finish after the response, and late results have no ledger effect. Each route imports its pipeline from its own `pipeline/` folder (`routes/weapons/pipeline/` and `routes/arenas/pipeline/`: `IsWeaponPipelineAvailable` and `RunWeaponPipeline`, and the arena pair; `@gunsmith/ai`'s `generateWeapon` / `generateArena`, with models built **per request** from the `ANTHROPIC_API_KEY` secret by ai's `createWeaponModels` / `createArenaModels`, and for arenas the engine's `BUILT_IN_ARENAS` to fall back on). **The pipelines are wired (2026-11-20) and gated by that one secret:** `isWeaponPipelineAvailable` and `isArenaPipelineAvailable` answer whether it is set and non-empty, so with none both routes answer 503 `ai-unavailable` and take no credit or spend; setting it is the act that lets a request cost money (the user's to authorise). `withTimeLimit(signal => run…(prompt, signal), 30 s)` hands the pipeline an `AbortSignal` that aborts, with `PipelineTimedOut` as its reason, when the limit goes by: no stage starts, the model call in flight is told to stop and the pipeline rejects, which the route's existing 504/refund/settle-in-full branch already handles. Tests mock the two modules (and, for the run functions, `@gunsmith/ai`), so no test calls a model. **Locally** `pnpm api:dev` binds it from the root `.env.local` (it is in `wrangler.jsonc`'s `secrets.required`); the managed acceptance Worker passes no env file, so no spec can spend. **Not yet in `infra/` or the CI deploy** (ship; the user adds the GitHub secret). **An arena request may name a `style` (`blue` or `red`, `@gunsmith/shared/arena-style/`; 2026-11-23):** `reserveCredit` reads it from the body for the arena kind only (`routes/shared/prompt-request/ParseStyleRequest`: absent is allowed, anything but exactly `blue` or `red` is a 400 `bad-request` before anything is taken), `CreditReservation.style` carries it and `runArenaPipeline(prompt, signal, style)` hands it to `generateArena`. A weapon request's `style` is ignored. `ArenaOutcome.arena` is still `unknown` (ai's draft; the answer drops `nodes`, `modelCalls` and `refunded`). Tests use `routes/shared/fake-ledgers/FakeLedgers` (budget's real `CreditAccount` behind a fake namespace, recording each call as `reserve:<kind>` so a wrong kind shows even while prices are equal) and each route's `property-tests/` (`pnpm test:properties`).
- **The library is generated items kept by id (2026-11-19, the user's rule: the page never sends a weapon or arena body).** A created result from `POST /api/weapons` or `/api/arenas` is kept in D1 (`accounts/schema/GeneratedItems`: id, account, kind, prompt, JSON payload, `saved_at`) before the credit is settled, and the answer carries its `id` (`routes/shared/keep-result/KeepCreatedResult`; a failed keep refunds the credit and answers 502). `routes/library/LibraryRoute` serves `GET /api/library` (`{limits, weapons, arenas}`, each item `{id, prompt, savedAt, weapon, appearance}` or `{..., arena}`), `POST /api/library` `{id}` (200 `saved`, also when already saved; 404 `not-found` for an unknown or another account's id; **409 `shelf-full` `{kind, limit}`**, nothing is dropped) and `DELETE /api/library/<id>` (off the shelf; the item stays kept so its id still works; 404 for another account's). `SHELF_LIMITS` (`routes/library/limits/ShelfLimits`, 8 weapons and 3 arenas, the user's numbers) is the one place the limits live. The limit is checked **in the same SQL statement that saves** (`accounts/save-item/`), so saves arriving together cannot overfill a space; `accounts/` held to one contract on in-memory and real D1 (`testing/contract/AccountsContract`). Unsaved generations stay in D1 (no pruning yet); the single migration was regenerated for the table.
- **`routes/credits/` is the balance read (budget, 2026-11-19).** `GET /api/credits` from a signed-in player (`CreditStatusRoute`) answers `{balance, dailyAllowance, prices, aiOn, returnsAt?}` from `CREDITS.balance()`, `SPEND.status()`, `CREDIT_PRICES` and `DAILY_CREDITS`. Read-only: it never reserves, settles or refunds (`property-tests/` holds that for any run of reads). 405 `Allow: GET`, 401 without a session.
- **Sign-in is Google OIDC with PKCE and D1 sessions (2026-11-19; `docs/sign-in.md`).** `GET /api/auth/google?return=` (`routes/sign-in/start/`) keeps a random `state`, a PKCE verifier and the **whole-origin-checked** return address in a short `HttpOnly` cookie and redirects to Google; `GET /api/auth/google/callback` (`sign-in/finish/`) compares the state, exchanges the code, finds or makes the account (id = a fresh `crypto.randomUUID()`, never Google's `sub`; no email or name is stored, the display name is two generated words) and starts a **session**: a 256-bit token in an `HttpOnly; Secure; SameSite=Lax` cookie for 30 days, of which D1 keeps only `sha256(token)`. **Every failure redirects back signed out** (one closed-event `console.warn`, never a code, state, subject, address or cookie); `POST /api/auth/logout` ends the one session and succeeds with none; `GET /api/me` is always 200 `{signedIn, displayName?}` and never touches D1 without a cookie. `LOGIN_LIMITER` (10 a minute per address) fails open. With no `GOOGLE_OAUTH_CLIENT_ID`/`_SECRET` every attempt returns signed out, so guests, rooms and acceptance need none. **`DELETE /api/account` (`routes/account/DeleteAccountRoute`, 2026-11-19) removes the signed-in player's account but does not reset their allowance (the user's rule: otherwise delete-and-sign-in is a denial-of-wallet loop).** `removeAccount` takes `{subjectDigest, keepUntil}` and, in one D1 batch, writes a `deleted_accounts` row (the **keyed HMAC-SHA256 of the Google subject** under the `ACCOUNT_DIGEST_KEY` secret, the opaque id the credit ledger knows the account by, and `keepUntil` = now + `DELETED_ACCOUNT_RETENTION_DAYS`, **90**, `routes/account/retention/`) and deletes the user (sessions and kept items go by cascade). **The ledger is not erased at deletion.** `GET /api/auth/google/callback` asks `claimDeletedAccountId(digest, now)` (`DELETE ... RETURNING`: used up once, ignored once expired) and gives the new account the old id, so the balance is the one it had; with no key set nothing is asked, and a failed read signs the player out rather than hand out a fresh allowance. After `keepUntil` the record is swept (`sweepDeletedAccounts` through `account-retention/EraseExpiredCredits`, run on each deletion and daily at 04:00 UTC from `ApiWorker.scheduled`) and the ledgers it named are erased one by one (a failure logs one closed `console.warn` `{route, outcome, error class}` and never fails the request). No key: 503 `deletion-unavailable`, nothing removed. No live session: 401. D1 failure: 500 `account-deletion-failed`, session and cookie kept. Success: 204 with `routes/shared/session/ClearedSessionCookie`. The digest is still personal data while kept (`docs/privacy-and-data.md`); a different Google account is not recognised.** **Layering (ESLint enforces it):** Drizzle and D1 live in `src/accounts/` alone (**one plain function per operation, each in its own folder with its unit test beside it**: `find-or-create-account/`, `create-session/`, `account-of-session/`, `delete-session/`, `remove-account/`, `claim-deleted-account-id/`, `sweep-deleted-accounts/`, and the shelf's four (below); the one root file is `Database.ts`, whose `database()` opens `workerEnvironment.DB` per call; `schema/`, `types/`, and `testing/` grouped as `in-memory/`, `local-database/`, `contract/`), `oauth4webapi` in `src/sign-in/` alone (`GoogleAuthorizationUrl`, `GoogleSubjectOf`, `IsGoogleConfigured`), and `cloudflare:workers` only in `env/WorkerEnvironment` (the Durable Object classes extend its `DurableObject`). **Tests:** `src/testing/SetupApiTests.ts` runs before every test file and `vi.mock`s what is outside the process (the account functions onto `accounts/testing/in-memory/TestAccounts`, in memory; the two Google functions onto `sign-in/testing/TestGoogle`; the four pipeline modules, automocked and defaulting to available), resets those fakes and **clears every key of `workerEnvironment` after each test**, so a test sets the bindings it needs (`workerEnvironment.CREDITS = ...`, `fakeLedgers()` does it for the ledgers) and nothing leaks. **Each function's own test runs the real function on real local D1** (`testing/local-database/UseLocalDatabase`: wrangler's `getPlatformProxy` in plain node, migrations applied, an empty database per test set as `workerEnvironment.DB`; the test arranges and asserts with raw SQL so it exercises that function alone, and `vi.unmock`s it). `testing/contract/AccountsContract` is the parity check: the same cases run on the in-memory functions (`testing/in-memory/InMemoryAccounts.test.ts`) and on the real ones together (`testing/contract/RealAccounts.test.ts`). A test of a mocked function itself calls `vi.unmock` for it. SQL is `migrations/` (`pnpm db:generate -- --name=<change>`, read it, then **Wrangler applies it**: `pnpm db:migrate:local`, never `drizzle-kit migrate`/`push`; Prettier ignores the folder). **Production D1 already exists.** Keep the applied migration names and SQL unchanged. Generate a separate migration for every schema change.
- **A request is checked for its origin before any route (`router/origin-check/IsForgedRequest`).** A `POST`/`PUT`/`PATCH`/`DELETE` or a WebSocket upgrade whose `Origin` is not trusted (a missing one included) answers 403 `forbidden-origin`; reads and the OAuth callback are not asked. Trusted means the whole origin is in `ALLOWED_ORIGINS` (`wrangler.jsonc`: the site) or, only when `ALLOW_LOOPBACK_ORIGINS` is `"true"`, a plain-http localhost/127.0.0.1 page at **any port**. That flag is passed **only by the start scripts** (`pnpm start`'s `--var`, the managed acceptance Worker in `PreviewServers.ts`), never declared in `wrangler.jsonc` or `infra/`, so a deployed Worker cannot have it. Any new local way to start the Worker for a browser needs the flag.
- `durable-objects/credit-ledger/` and `spend-ledger/` are budget's: AI credits and spend (`docs/cost-and-budget.md`). Each domain has one root file, a Durable Object (`credit-ledger/CreditLedger.ts`, one per account; `spend-ledger/SpendLedger.ts`, the one global), that only wires; the decisions are plain **synchronous** classes beneath it (`credit-ledger/account/CreditAccount.ts`, `spend-ledger/meter/SpendMeter.ts`). Keep them synchronous: the object runs one request at a time, so no `await` between a read and its write is what makes a reserve atomic. Time is passed in as a parameter (only the Durable Object reads the clock). `shared/utc/UtcDay.ts` is shared by both. `spend-ledger/estimate/` holds one folder per route: `weapon/` (the tunable `WEAPON_SPEND`, a worst-case reserve and a per-call price, and `SettledWeaponSpend`) and `arena/` (`ARENA_SPEND`, a price for each call by its place, and `SettledArenaSpend`), each settling at the tokens the outcome's `usage` reports, priced by `estimate/tokens/PricedUsage` (Haiku 5.5's $0.10 in and $0.50 out a million, rounded up; `undefined` for no usable usage), and falling back to an estimate from the outcome's `modelCalls` when none was reported. `SpendLedger.alarm()` emails the 50/80/100% budget alerts through the `ALERT_MAIL` `send_email` binding (`spend-ledger/alerts/`: `SendDueAlerts` marks an alert sent only after its email has gone, so a failure is retried; `email/DeliverAlertEmail` is the untested `cloudflare:email` edge, with its pure builder beneath it; the 100% alert is due once a request is refused for crossing the monthly cap, since spend then stops short of it); `ALERT_TO_ADDRESS` is a secret and, unset, nothing is sent. `CreditLedger.erase()` (the one method that awaits: a single `deleteAll`) is what `DELETE /api/account` calls for a deleted account's ledger **once its retention has run out** (never at deletion, so deleting does not reset the allowance); the fake ledgers' stub records `erase` and drops that account.
- **Fog is the engine's** (`@gunsmith/engine/seat/ViewOfSeat`): the server sends each seat exactly `viewOfSeat(world, seat)`, so a hidden fighter is absent from the frame. Never build a snapshot another way. `TwoBrowsersHidingFromEachOther` reads the received frames to prove it.
- **The pre-round chooses the weapons and the arena before round 1 (2026-11-20).** `durable-objects/match/pre-round/PreRound.ts` is plain state like `MatchRoom` (which owns one). It has two steps a seat takes in any order, each locked in on its own. **Weapons:** a seat puts two weapons forward (`chooseWeapons`, slot 1 then slot 2): each a **built-in by key** or a **saved weapon by id**, held as a `ChosenWeapon` (the saved one carries the weapon and drawing the room already checked, plus its id, which never leaves the room; `weapons/BuiltInWeaponKeyed` finds one in the engine's `BUILT_IN_WEAPONS`) forward and locks them in (`lockInWeapons`; a seat that chooses none gets the rifle and the marksman rifle, `DEFAULT_WEAPON_KEYS`); the other seat's pair is hidden until **both** have locked in theirs, and a locked pair cannot change. **Arena:** each seat puts a **built-in arena by name or a saved one by id** (`chooseArena`, a `ChosenArena`; two seats put forward the same arena only if both are the same built-in name or the same saved id, so two saved arenas with one name are two arenas) forward and locks it in (`lockInArena`; a seat that chooses nothing puts forward the Duel arena); a seat sees the other's arena only once **both** are locked in, and before that only a `locked` flag. The same arena twice is the arena (`how: "same"`); two different arenas are both shown and each seat picks one, random or nothing (`pickArena`), and engine's `resolveArenaPicks` settles it from the room's `makeSeed` (`how` is the engine's, e.g. `coin`). **The pre-round opens when the first seat sits and a seat on its own has no limit of time** (the user's rule: a lone player may choose, lock in everything and visit the workshop); the clock (`DEFAULT_PRE_ROUND_SECONDS`, 60) starts when the second seat sits, and when it runs out a seat that has not locked in gets the Duel arena (a draft counts for nothing) and one that has not picked picks nothing, and a seat whose weapons are not locked in gets the default pair (a draft counts for nothing), so the room never waits on a person. The pre-round is decided (`outcome()`: arena, how, and each seat's `WeaponPair`) only when the arena is settled **and** both seats' weapons are locked in; the room then builds every round with `room/weapons/WorldWithWeapons` (the first seat is the world's player, the second its opponent; both weapons full, the first in hand), so each seat's weapons carry into every round. **No carry-over from an earlier match (the user, to stop hiding weapons).** A seat that leaves while alone is given back with what it chose (`PreRound.release`; the browser makes its choice again), but once both have sat the seat is kept like a match's (`MatchRoom.isCommitted`: token, reconnect, a stranger refused). The forfeit clocks begin with the match, not the pre-round. The match begins as the pre-round decides (`beginMatchIfDecided`): `joined` carries the room's **current** arena (the Duel backdrop until decided, the decided one after, so a returning browser is told the right one), and `takeArenaMessage()` gives one `{kind: "arena", rows}` that `Match` sends both browsers once. Wire in (`messages/ParsePreRoundMessage`): `{kind: "choose", step: "arena", choice: {kind: "builtIn", name} | {kind: "saved", id}}`, `{kind: "lockIn", step: "arena"}`, `{kind: "choose", step: "weapons", choice: [Choice, Choice]}` (exactly two, each `{kind: "builtIn", key}` or `{kind: "saved", id}`; an id is a non-empty string of at most 64 characters), `{kind: "lockIn", step: "weapons"}`, `{kind: "pickArena", pick: {kind: "arena", seat} | {kind: "random"} | {kind: "nothing"}}`; out (`PreRoundMessage`, each tick instead of a snapshot until the match begins): `{kind: "preRound", stage: "choosing" | "picking" | "decided", secondsLeft?, own, opponent, how?}`, where `own` and `opponent` each carry `arena?` (an `ArenaView`), the other flat fields and `weapons: {locked, choices?}` (a pair of `WeaponView`s; the opponent's only once both weapons are locked in). **`?preRoundSeconds=`** on the page address is read from the room's first connection (`pre-round-seconds/ParsePreRoundSeconds`: shorter only, `0` or less means none, so the match begins as the second seat sits): the acceptance DSL's `addressOfRoom` always sends `0` unless a spec is about choosing. `MatchRoom` takes one options object (`MatchRoomOptions`: `limits`, `makeToken`, `makeSeed`, `preRoundSeconds`). **Saved items (2026-11-21, partly built):** `router/routes/socket/SocketRoute` reads the session and hands `Match` the account in `X-Seat-Account` (`seat-account/SeatAccountHeader`; the Worker drops any a page sent, so it proves nobody else); `Match` keeps the latest connection's account per seat and runs each seat's pre-round frames **in order** (`afterEarlierFrames`) because a saved id waits on the database. `choices/ResolveArenaChoice` and `ResolveWeaponChoices` turn a wire choice into a `ChosenArena`/`ChosenWeapons` (a guest's `saved` is refused, the whole weapon pair is refused if either is). **The saved branch is not built:** it reads the account's shelf (`savedItemsOfAccount`) and parses the stored payload with engine's `parseStoredWeapon`/`parseStoredArena` (`@gunsmith/engine/library-items/`, on main since `2f5cb87`) and shared's `appearanceSchema`; until it is written a saved choice is refused for everyone. A saved weapon's `identity.key` is the fixed `"saved"` (the engine's choice: a library id must not reach the other player). **Views never carry an id or a body:** a saved weapon is `{kind: "saved", name}`, a saved arena `{kind: "saved", name}` plus `rows` only in the other seat's view once both are locked in. **`reveal`:** once, when the match begins, each seat gets `{kind: "reveal", weapons: {own, opponent}}` (`MatchRoom.takeRevealMessage(seat)`, `room/reveal/RevealFor`; each weapon `{kind: "builtIn", key}` or `{kind: "saved", weapon, appearance}`), because the match begins in the action that decides it and no `preRound` frame follows. **Not built:** the reveal hold, the idle forfeit during choosing.
- The default arena is engine's Duel (`@gunsmith/engine/built-in-arenas/DuelBuiltInArena`), what a seat gets that chooses nothing.

## Conventions

- **Decide in plain functions and plain classes; keep the runtime at the edge.** A class is for state (`MatchRoom`) or the Durable Object itself.
- Property tests (`fast-check`, `durable-objects/match/property-tests/**/*Invariants.test.ts`: the room's in `match-room/` with its arbitraries, `step-checks/` and `score-checks/` beneath it, the parser's beside it) are left out of `pnpm checks` and run with `pnpm test:properties`, as the engine's do.
- Tests run in plain node (`vitest.config.ts`): `@cloudflare/vitest-pool-workers` peers on vitest 4 and the workspace is on 5. A route takes a `Request`; a test sets what it reads on `workerEnvironment` (a fake `MATCHES` namespace, a limiter) and `SetupApiTests` empties it afterwards.
- Pacing is `durable-objects/match/tick/MatchTick.ts`: a clock 30 times a second plays the engine's 1/60 s steps that real time owes (`StepsOwed`, so a late timer does not slow the game) and sends a snapshot after each. The browser predicts its own fighter and blends the other between snapshots (`webapp/src/online/`), so 30 is enough; at 20 the plain local-feeling game was choppy only because nothing smoothed it. The wire carries `seq` on each input and `ack` (`seq`, `held`) on each snapshot (`@gunsmith/shared/online/types/InputAck`) so the browser knows which of its inputs the server has played.
- Not built yet, on purpose: saving a prompt with no result, saving the opponent's items, pruning unsaved generations, the matchmaker, a pickup chosen by a seat's own loadout, an "opponent is away" notice for the player who stays, spectators, rate limiting beyond sign-in, recordings. Add each when a spec needs it.

## Running

```bash
pnpm --filter @gunsmith/api db:migrate:local   # once, and after each new migration: the local D1 (`.wrangler/state`); sign-in needs it, guests do not
pnpm api:dev                 # the Worker on :8787 (API_PORT=8790 pnpm api:dev for another port); trusts localhost pages at any port
pnpm start                   # the webapp; its /api proxy (with WebSockets) points at :8787, or at API_URL
```

For an acceptance run, serve the build with `API_URL=http://localhost:<worker port> pnpm --filter @gunsmith/webapp exec vite preview --port <port> --strictPort`, and point `WEBAPP_URL` at it. Use your own ports and stop only your own servers. For the real Google flow keep `GOOGLE_OAUTH_CLIENT_ID` and `GOOGLE_OAUTH_CLIENT_SECRET` (and `ACCOUNT_DIGEST_KEY`, any long random string, without which `DELETE /api/account` answers 503) in the one git-ignored `.env.local` at the project root: `pnpm api:dev` passes it to Wrangler with `--env-file` when it exists (no `api/.dev.vars`, which would take precedence), and sets `GOOGLE_REDIRECT_URI` itself from the port (`http://localhost:<port>/api/auth/google/callback`, which must be registered with the OAuth client). The manifest limits secret bindings from that file to the OAuth pair, `ALERT_TO_ADDRESS`, `ACCOUNT_DIGEST_KEY` and `ANTHROPIC_API_KEY` (**with it in the file, `pnpm api:dev` can spend real money** on a signed-in player's generation request). Agents never read it.
