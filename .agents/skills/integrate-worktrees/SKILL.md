# Integrate Worktrees

Run from the **main checkout**. A full-batch request is a **super turn**. The user's invocation is the signal to start. Check the worktrees directly. An explicitly targeted integration reviews only the requested deliveries and leaves the return sync to the personas.

This skill is the executable form of steps 6-9 of [the worktree flow](../../../docs/agent-reference/Operations.md#development-worktrees-and-the-integration-checkout). Claude Code and Codex share this one file (`.claude/skills/integrate-worktrees` is a symlink to it). If this file and `Operations.md` disagree, `Operations.md` wins; fix this file afterwards.

## Establish scope and evidence

- Read the root instructions, `TODO.md` startup and status board, `HANDOFF.md` and the integration guidance. Read package and nested instructions and nearby implementation/tests for incoming changes.
- Discover the seven persona checkouts from the status board and `git worktree list --porcelain`. For a super turn, verify that `main` and every persona checkout are present, on the assigned branch, clean (including untracked files), unlocked and free of pending Git operations. If a persona checkout is blocked, name it and its blocker, then ask whether to skip that specific worktree. Wait for the answer before continuing. Skip approved checkouts and their deliveries for this run, report the exclusions, and preserve those checkouts for a later run. A blocked `main` stops the run.
- Inventory with `git -C <path> status --porcelain=v1 --branch` and `git log --reverse --oneline <main-tip>..<source-tip>`. Include every eligible worktree in a super turn, even those with no unique commits. In a targeted integration, include requested locked or dirty sources in read-only review and merge only their committed tips.
- Record each source's absolute path, branch, exact tip, status and index fingerprint before integration. `git ls-files --stage -z` can be hashed without reading file contents. Keep evidence in temporary storage (the session scratchpad or `/private/tmp`), not source checkouts. Never read secrets, `.env*` files or secret-bearing diffs; a secret-guard hook may block them, and if it fires do not look for another way round it.
- Inspect commit contents from Git objects (`git show`, `git diff` between explicit revisions), not dirty worktree files. Review behavior, tests, consumed interfaces, dependencies, assets and delivery notes. Existing branch validation is inherited evidence, not a fresh combined result.
- Recheck the included worktrees after review and before the first merge. If the user approves skipping a newly blocked worktree, exclude it before merging. Both modes require a clean `main` with no pending Git operation. A request authorizes the necessary Git writes in the requested mode, including the return fast-forwards in a super turn. Follow any tool-level approval requirements.

## Merge reviewed commits

- Choose dependency order from actual consumers and overlapping changes; integrate one delivery at a time. Freeze the reviewed tip for each merge so moving branches cannot silently add unreviewed commits.
- Use `git merge --no-ff --no-commit --no-overwrite-ignore <reviewed-tip>` for each tip that `main` does not already contain. Inspect the staged result, resolve permitted conflicts and run affected checks, then commit as `chore: merge <source-branch> into main`. Add the commit attribution trailer the session instructs, if any.
- Resolve straightforward conflicts yourself when authorized: combine independent delivery notes, keep each owner's latest status, and preserve both compatible code behaviors (shared docs keep both sides; code is merged by meaning). Do not choose whole-file ours/theirs for shared coordination files. Handle diff3 and nested virtual-ancestor markers carefully; inspect the final content and scan for remaining markers.
- Reconcile current status separately from historical delivery logs: remove stale claims that integrated work is still uncommitted, close delivered requests, and retain genuinely unfinished follow-ups. A delivered asset is not evidence that runtime integration exists.
- Ask the user about conflicts where the two sides disagree on behavior (not wording), incompatible interfaces, loss of meaningful work, or uncertain intent. Report the file and concrete alternatives. Leave the merge state intact while awaiting advice; do not reset or abort automatically.
- Main stays integration-only. Do not introduce feature fixes or refactors there to make checks pass. Diagnose a real defect and arrange a committed fix through its owning persona worktree, without modifying someone else's unfinished work.
- Preserve working files in each checkout. Existing restrictions on committing source work, rewriting history, removing or unlocking worktrees, pushing, deploying, dependencies and spending still apply.

## Validate the combined result

- Run the repository's typecheck, lint and relevant tests, using its documented combined gate (`pnpm checks`). Add the actual affected integration checks: production-build browser acceptance, engine properties, fake-only AI evals (`pnpm evals`), asset/codec or render verification. Inspect scripts first; do not assume command names or include paid/local model calls without authorization.
- Give browser checks a separate strict port and their own production-preview server. Never reuse or kill another session's server. Prefer the managed startup/cleanup scripts. Run independent checks in parallel only when their resource use and output paths permit it.
- Distinguish failures from permission, startup, timeout and existing-flake evidence. Retry after correcting a demonstrated environment problem, preserving the first result. Abnormally long timings justify investigating system suspension or resource contention; on macOS, `caffeinate -i <check>` can prevent idle sleep during a justified rerun. Do not assume a cause or retry repeatedly until green. If a failure reproduces, investigate or report it; never weaken assertions or tolerances to complete a merge.
- Perform the instruction-required standards and folder/caller review separately from automated checks. Do not claim lint proves layout, ownership, usability or model quality.

## Record and return the validated revision

- Verify each reviewed tip with `git merge-base --is-ancestor <tip> HEAD` from `main`. Compare the source tips, statuses and index fingerprints with the initial inventory before any return sync. In a targeted integration, review newly committed deliveries within the original scope and rerun the affected checks. Report concurrent changes and leave source checkouts to their owners.
- A super turn holds its reviewed tips fixed. If one moves or a checkout becomes blocked, pause the run and name the checkout. Continue only after a fresh inventory and review or the user's approval to skip it. Keep any merges already made and report any checkout you omit from the return sync. A failed combined check also stops the return sync. Preserve the integration commits and route any fix through its owning persona.
- After validation, record the reviewed tips, merge hashes, tested revision, actual results, conflict decisions and limitations in `HANDOFF.md` and update `TODO.md` where applicable. Validate and commit the coordination record before pinning the final `main` SHA. On a resumed run with no new deliveries, reuse recorded validation only if it covers the pinned code/assets revision. Otherwise revalidate, including changes since the last validated revision. An already synced run needs no new record or commit.
- For a super turn, repeat preflight for `main` and the included worktrees before the first return sync. Immediately before each fast-forward confirm that the checkout still matches its inventory and `main` still matches the pinned SHA. Run `git -C <persona-worktree> merge --ff-only --no-overwrite-ignore <final-main-sha>` for each included persona whose `HEAD` differs. If one fails, report which worktrees advanced and why. Pause until the user approves skipping the blocked checkout or the blocker clears. Already synced worktrees are included in preflight and skipped during the return sync.
- Finish by verifying that `main` is clean with no pending merge. For a super turn, verify that `main` and every included persona checkout are clean and at the pinned SHA. Report that SHA, the integrated tips, validation results, the actual sync status and approved exclusions. Stop only the servers and processes you started.
