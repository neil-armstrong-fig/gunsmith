# AGENTS.md: webapp

The React app: Vite, React 19, Tailwind v4, react-three-fiber. The game is the whole window; menus will appear over it
only when needed. Root coding standards and the package layering below apply.

## Layout

```
src/
  Main.tsx, index.css        the entry and the palette tokens
  react/                     top layer: everything drawn, and the logic only one component uses, beneath that component
  react/hooks/               generic hooks that no one component owns (`use-pressed-key/`, `use-held-keys/`), kept together so they are easy to spot (the user's exception to "keep it close", 2026-11-19)
  store/                     middle layer: Zustand stores; may import game/ and the engine, never react/
    game/                    the game store: the engine's `World` and nothing else
    app/                     the app store: choices about the game around the match (`muted`, `reducedMotion`, `shakePixels`, `workshopOpen`; online, the ask for the next round, whether the other player is being waited for and whether the connection is being made again)
    feedback/                the feedback store: the cues of the fight (`bulletHits`, `ringHurting`, `hitMarks`), written by the loop after every step
    workshop/                the workshop store: the prompt being written, the weapon last made, the words that made it and the shelf id it is saved under (`prompt`, `weapon`, `madeFromPrompt`, `savedId`); lint allows zustand, engine types and its own folder
    shelf/                   the shelf store: the weapons a player has saved (`weapons`, `weaponLimit`), kept in this browser's local storage; same lint allow-list
  sound/                     what the fight sounds like: plain logic and the browser's audio; used by react/, never imports react/ or a store
  assets/sounds/             the sound files (`files/<key>.<ext>`), their keys and addresses
  game/                      bottom layer: plain data and logic (the arenas and which match to open), no React, no store
```

An import may only point down: `react/` → `store/` → `game/`. ESLint enforces it (`eslint.config.js`): `game/` may not
import the store, React, the renderer or Zustand; `store/` may not import `react/`. A piece of logic only one component
uses still sits beneath that component, not in `game/`; `game/` is for data shared by several layers.

## State: Zustand, one library, a store per domain

Zustand is the only state library. A store is a folder under `store/` named for its subject (`store/game/`), laid out
like a Redux slice: **the store itself at the top** (`UseGameStore.ts` exports `useGameStore`, with its test beside it and
its state type in `types/`), and everything that reads from it in sub-folders, each with its own `types/`:

```
store/game/
  UseGameStore.ts, UseGameStore.test.ts
  types/GameStore.ts
  selectors/                   reads, each in a folder of its own
    select-ammo-readout/       a reactive selector for components
      SelectAmmoReadout.ts, SelectAmmoReadout.test.ts
      types/AmmoReadout.ts
    select-player-health/      the player's health, a plain number
    select-round/              where the round stands, a plain string
    select-match/              the best-of-three the world belongs to (the same object until a round is scored), or nothing
    select-seconds-until-ring/ whole seconds (rounded up) before the ring starts, or nothing when the world has no ring; changes once a second
    game-state/                `gameState()`, the one-off read for `useFrame`
      GameState.ts
```

Redux terms: `useGameStore` is the store (and `getState()` / `setState` live on it), `setWorld` is the one action, `GameStore`
is `RootState` plus the actions, and a selector is `(state) => derived value`, as in Redux. `gameState()` is the imperative
read, `store.getState().world`, that does not subscribe. New kinds of thing get a sub-folder named for what they are
(`selectors/` today), never files loose beside the store. The shape follows large Zustand codebases (Lobe Chat keeps a
folder per domain with the store, its initial state and its selectors) and the Redux style guide's feature folders alike:
group by subject, not by file type. Add a `slices/` folder inside a store only when that store has several slices.
Middleware, if any, goes on the composed store, never on a slice.

**The game store holds what the engine's `World` holds, and nothing else.** Its state is `{world, setWorld}`.

- A value worked out from the world (ammunition, health shown on screen) is a **selector**, never stored state.
- Menus, lobby, library, credits and meta state do **not** go here: they go in an app store (`store/app/`), built when a
  screen needs it, with the same conventions. Two stores because a Zustand `set` runs every mounted selector of its
  store: a world written 60 times a second must not share a store with the whole UI.
- It is enforced, not only written: lint lets `store/game/` import only `zustand`, the engine, `@src/game/**` and its own
  folder, and `UseGameStore.test.ts` pins the store's exact keys, so adding state is a deliberate edit.

**Reading it.** The loop writes the world once per frame (`setWorld`), and only when a step ran. `useFrame` and the loop
read it with `gameState()`, which does not subscribe and causes no render. A React component reads slow values with a
selector and `useShallow`: `useGameStore(useShallow(selectAmmoReadout))` re-renders only when the readout changes, which
is a few times a second at most. A per-frame value is never bound to a component (react-three-fiber's own guidance: state
managers are fine for updates that are not rapid). The decision and its sources are in `docs/state-management.md`.

## Runtime boundaries

- `online/` (`?room=<code>`) is this browser's end of an online match; the server plays it, `OnlineMatch` makes it feel like the local game. The own fighter is predicted (each fixed step the input is sent when it changes, plus a heartbeat, and played at once with the engine; each snapshot says how far the server has played them, `ack`, and the rest are played again on top of its word, a small disagreement eased out over a fifth of a second and one over a tile put right at once), the other fighter is drawn about 100 ms behind the newest snapshot on a render clock that holds when snapshots are late (`interpolation/`), and the game store still holds only a `World` (`worldToShow`). Shots are not predicted. The server scores the best of three: "Next round" and "Play again" in a room only ask (`round-banner/go-on/GoOn` puts an ask in the app store, the loop sends `{kind: "ready"}` through `OnlineMatch.readyForNextRound`, and the banner says "Waiting for the other player" while the server's `ready` flag for this seat is set); the next round begins when both have asked. **Reconnecting:** the socket is a `ReconnectingSocket` (`online/socket/reconnecting/`), which opens another connection after a loss (waiting 250 ms, doubling to 4 s) and gives up on close codes 4409 (room full) and 4410 (seat taken over by another page). The seat's token from `joined` is kept by `SeatTokenKeeper` in the tab's **session** storage (a reload gets the seat back, a new tab does not) and shown on each connection. Each `joined` (the server sends one per connection) restarts the browser's input count from zero and the ask in force is sent again; **nothing is sent on a connection until its `joined` has arrived** (an input numbered from the old count, sent in that gap, made the server drop every later one). While the connection is being made again the app store's `reconnecting` is set from `OnlineMatch.isReconnecting()` and `connection-notice/` says so. `?lag=<ms>` holds every frame up that long each way, to feel it on localhost. `?reconnectSeconds=` and `?idleSeconds=` on the page are passed on the socket URL (`RoomSocketUrl`), so a spec can make the room wait seconds instead of 30 and 60; the server reads them from the room's first connection only. The online branch of `UseGameLoop` and `online/` are server's; play keeps the local path.
- `game/scenario/` chooses seeded setup once from the query. Query parameters configure a scenario, never write live state. Preserve the match score and setup when starting another round.
- Render the engine's visibility result; do not invent a second sight/height rule in React. Keep terrain dim outside the cone while suppressing hidden entities and their effects.
- HUD animation on a timer uses CSS; per-frame geometry and uniforms use `useFrame`. Update shader uniforms through `materialRef.current.uniforms`, not the object originally passed to JSX.
- Store GLSL in `.glsl` files, imported with `?raw`, and compile it with `glslangValidator` in tests. A valid shader still needs a browser drawing assertion where feasible.
- The reticle cursor belongs on the arena only. HUD pointer pass-through must not create aim dead zones; buttons and overlays retain normal interaction. A button click must not fire a weapon. Native/Retina cursor appearance requires manual inspection.
- `sound/` imports no React or store. Consume the engine's local combat events after every simulation tick, because the game store retains only the last world. Muting belongs in the app store.
- **Placed sounds and online sound** (2026-11-20): `SoundOutput.play(key, options?: {pan, gain})`; `sound/spatial/` maps the engine's `heard {sound, sector, loudness}` to the ears (`panOfSector`: east right, west left, diagonals 0.707, north and south the middle; `gainOfLoudness`: 1, 0.5, 0.2) and `sound/heard/HeardSounds` plays it (only the pickup has a file; add a shot and a footfall to `FILE_OF_HEARD_SOUND` when art delivers them). The server sends no per-speaker level, so nothing finer than sector and band can reach a cheater. In a room, `OnlineMatch.takeEvents()` gives the events and game seconds of the snapshots since the last call and the loop's room branch calls `sounds.afterTick` once per snapshot (never every frame: a frame with no news must not stop the ring loop). Screen cues are still local only.
- Drop sounds while the audio context is suspended; never queue them for later playback. Preserve the once-per-hold empty-click latch. `sound/damage-crunch/DamageCrunch` makes one crunch (`sfx-damage-crunch`) per burst of bullets (hits within `BURST_SECONDS`, 100 ms of game time, are merged; the window is not stretched). Local ring damage plays one continuous `sfx-ring-damage-loop` voice while the player takes damage, with 100 ms gain fades on start and stop. The hit that ends a round still crunches; nothing after it does. The loop passes each step's `seconds` so `sound/` reads no clock.
- **Damage on the screen** follows art's study (`docs/art/concepts/combat-feedback/Handover.md`, "Clarifications"). The loop calls `use-game-loop/feedback/RecordFeedbackCues` after every step with `World.events` and the round, and `cues/CuesAfterTick` turns them into `store/feedback/`'s `{bulletHits, ringHurting}` (a step with a bullet hit is one more hit, even the one that ends the round; the ring hurts only in a step it did and only in a round being fought), written only when a cue changed. Three things read it, none through per-frame React state: `arena-scene/components/damage-brackets/` (a `[ ]` pair round the player for 180 ms, opening 8 study pixels; `flash/NextFlash` starts a flash on a new hit and merges hits inside `BURST_SECONDS`, 100 ms, into the running one), `ring-highlight/` (a thin coral circle round the player while the ring hurts; the user dropped the study's slashes and bottom band) and, on the health panel, a red border while the ring hurts. `health-hud/` also holds `HealthTrail`: an amber bar that follows health down in 350 ms **for bullets only** (a fall that comes with a new hit; the ring's loss and a rise at a round reset snap it). `ring-edge/` draws nothing until the ring has started to close (`closingProgress > 0`): its starting radius reaches exactly to the farthest corner, so its edge would show there as a wedge. Brackets and highlight sit above the player (`z` 1.2) and are always about the local player, so nothing of the opponent shows. The store's lint allow-list is zustand and its own folder.
- **Camera shake and reduced motion** (slice 4). `hooks/use-camera-shake/UseCameraShake` shakes the camera for 100 ms from a new `bulletHits` (never the ring; the same `arena-scene/flash/NextFlash` as the brackets, so a burst is one shake): art's curve, horizontal `sin(age × 180) × pixels × (1 − age / 0.1)` and vertical minus half of it (`shake-offset/ShakeOffset`), 12 screen pixels by default (the user's choice after trying 8 to 16; the study's 2 was too subtle), moved onto the camera by `camera-position/CameraPositionOf` and read back off the camera as applied by `ShakeOfCamera` into `data-camera-shake="x,y"` on the canvas, which is what acceptance reads. **Aiming never sees it**: `arenaPointAtPixel` stays on the still camera (the user's decision, 2026-11-17), so a hit cannot nudge the aim; the picture is up to 12 px off the cursor for 100 ms. It is a separate `useFrame` after the fit in `ArenaScene` (the fit returns early when the zoom is unchanged). `?shake=<pixels>` tunes it and `0` is off. Reduced motion (`?reducedMotion=1` or `prefers-reduced-motion`, read once at load by `game/motion/`, held in the app store) removes the shake, the brackets' opening and the health trail (the bar snaps). Local held weapon drawings are integrated. Cosmetic recoil and muzzle flash remain Play follow-ups.
- **The workshop** (`react/components/dom/workshop/`, first slice, 2026-11-19; concept in `docs/selection-concept/`). **B** opens a panel over the dimmed practice range (`hooks/use-workshop-key/`, practice scenario only: nothing is made in a match), **Escape** shuts it, and `workshopOpen` in the app store makes `UseGameLoop` return before it steps (after the online branch, which is server's; the owed steps are dropped, not made up). The panel's root stops `keydown` and `mousedown` so typed `r`, `1`, `2`, `m` or a click never reach the window listeners (the weapon-key latch keeps a pressed `r` or slot until the loop resumes, so a leak shows only after closing); focus moves into the panel on open so Escape works. The prompt and the last weapon live in `store/workshop/` so shutting and reopening finds them. `components/weapon-prompt/` (box, live count in characters against `WEAPON_PROMPT_LIMIT` 600 counted as `.length` like ai's pre-check, Make off when empty or over, text kept) and `components/weapon-card/` (name, `powerRatingOf` as 0 to 100, picture from `assets/weapon-pictures/`, six stat rows). **Make calls `stand-in/StandInWeaponFor`**: a built-in chosen by words in the prompt (sniper, long, scope: marksman; fast, rapid, submachine: submachine gun; else rifle), named "Stand-in …"; the real route replaces it. **Try it** (on the card) calls `weapon-on-trial/TryOnTheRange` (with `trial-world/WorldWithWeaponOnTrial`): the made weapon goes in slot 2 and in hand with a full magazine and reserve (slot 1 keeps the rifle, a reload is ended), written to the game store with `setWorld`, and the panel shuts; a second Try it replaces slot 2. **Free refills and the dummies:** pressing B fills both weapons before the panel opens (`hooks/use-workshop-key/` writes `hooks/full-ammunition/WorldWithFullAmmunition` with `setWorld`, then opens; not in an effect after render, where the loop could step first), and **T** (`hooks/use-practice-reset-key/`, practice scenario only, heard only while the panel is shut) writes `range-reset/WorldWithRangeReset`: every dummy back at full health where it stood and both weapons full. `game/practice/PracticeDummies` is a fan of four at about 3, 6, 9 and 11 tiles on four bearings (the rifle sees 12; the submachine gun's 9 sees two). **Save and the shelf** (2026-11-19): the card's **Save** (`weapon-card/components/save-weapon/`) puts the weapon on the shelf with the words that made it (`madeFromPrompt`, so editing the box after Make changes nothing), says **Saved** while the shelf still holds its id (`savedId`, cleared by a new Make), and with the shelf full asks which saved weapon to replace (a group, **Replace** per weapon, **Cancel**; the question is about one weapon, so a new Make ends it) and drops nothing until the player chooses. `weapon-shelf/` lists the saved weapons ("n of max", `shelf-count`) with **Try it** (the same `weapon-on-trial/TryOnTheRange` as the card), **Iterate** (`showSavedWeapon`: its words in the box, its weapon on the card, saved under its id) and **Delete**. `store/shelf/` is zustand's `persist` middleware on the one store: it keeps only the weapons (`partialize`) under `gunsmith.shelf.weapons` in `localStorage` (as `{state, version}`), and what it reads back, which it hands over as `unknown` unchecked, goes through `merge` into `browser-storage/ShelfWeaponsOfPersisted`, which parses each weapon with zod (`shelf-weapons-from/`: `ShelfWeaponSchema`, `WeaponSchema` built from the engine's `STAT_RANGES`, vision only above nothing), leaves out an item that does not parse, a repeated id and any extra field, and keeps the rest of the shelf. Where there is no browser the store uses a no-op storage (looking for `window`, not `globalThis.localStorage`, which Node warns about); a blocked storage leaves the shelf in memory, with persist's own warning. Change the stored shape with `version` and `migrate`, not by hand. `WEAPON_SHELF_LIMIT` (5) stands in for the server's per-account limit and is not yet a query seam (specs fill five). The shelf is read by nothing outside the workshop, so it never reaches a match or the opponent. Not built yet: the making, turned-away and timed-out states, prompt-only saves, Try again, arenas on the shelf, the opponent's weapon.
- **Hit confirmation** (`sfx-hit` and four mint `#8AD4B0` ticks at a target's corners for 180 ms, art's study; no expansion). The engine's `hitLanded {on}` is positionless and already only for a target the player saw, so nothing here judges sight to decide _whether_: `sound/hit-confirmation/HitConfirmation` plays one `sfx-hit` per burst (`sound/burst-window/BurstWindow`, shared with the crunch; the 100 ms merge is a decision, the handover is silent on it). _Where_ is found by `use-game-loop/feedback/hit-places/HitPlacesOfStep` (the opponent where it stands, each dummy in sight that lost health, where it stood) and written as `hitMarks` (last 8, numbered) to the feedback store; `arena-scene/components/hit-ticks/HitTicks` takes each mark once in `useFrame` (`ticks/NextTicks` merges a place's marks inside the burst) and **draws a tick only while `canSeePoint` still holds for its place**, so turning away inside the 180 ms reveals nothing. Local play only; online rooms return before the loop's step path.
- One-shots use MP3. The ring damage loop uses a byte-identical copy of the approved WAV to avoid WebKit's MP3 padding. Keep masters in `audio/` and emit runtime audio as separate assets with `?url&no-inline`. Safari audio was accepted as good enough by user decision on 2026-11-17; preserve recorded timing findings.

## Sprite rendering

SVG assets live in `public/assets/sprites/`; `assets/sprites/` owns keys, anchors and pixels-per-tile scaling. Preserve body-centre anchors and the same scale across stances. Rasterised textures render with `toneMapped={false}`. Missing/loading pictures use the existing placeholders; `data-sprites-ready` becomes true after every load succeeds or fails, and acceptance scenarios wait for it.

**Weapon drawings:** `arena-scene/hooks/use-weapon-drawing/` resolves one cached texture per weapon. `WeaponDrawingPlane` centres that texture at half scale on the ground or anchors it at the grip under the fighter's hand. The three built-in weapons use authored sprites. The existing `?weaponDrawing=lantern|refused` fixture supplies the sparring pickup's drawing, which follows the weapon into the loadout. The shared schema validates the fixture before the existing structural SVG rasteriser runs. Invalid appearance uses the code-owned stand-in. Production-generated weapons still need an appearance association supplied by the weapon contract.

**Arena terrain**: the three `tile-floor-l*` keys and `tile-wall` live in `public/assets/tiles/` and use the same manifest, loader and readiness signal. Each SVG covers one arena cell. `ArenaWalls` repeats low ground across its floor plane and draws the solid wall tiles. `ArenaHeights` draws the upper floors, matching stair bands to the floor palette, with the drop strips above. Pending or failed pictures use the flat materials. `?scenario=terrain` opens a playable three-level preview.

**Pickup marker**: `sprite-pickup-marker` uses the standard sprite loader and sits above the weapon in the same visibility-controlled group. The 88-design-pixel canvas is centred on the pickup and uses the same half scale as the weapon. When the file fails to load, the weapon or disc still draws.

**Shots** (`components/bullets/`): `Bullets` draws two instanced meshes (`shots/Shots.tsx`), the player's in art's blue (`fx-projectile-rifle-blue`) and the opponent's in orange (`fx-projectile-rifle-orange`, matching silhouette in `#FF9B54`, retained by user choice and art review on 2026-11-17). The manifest anchors a shot on its tip (49, 32), not the picture's centre, because a bullet is a point that hits when it touches something; `shots/placement/ShotPlacementOf` turns the offset with the bullet's `direction`. Fog is unchanged (`visibleToPlayer(world).bullets`). **The game loop's `useFrame` has priority −1** (`GAME_LOOP_PRIORITY`): at the default it ran after the drawing components and everything was drawn one fixed step (0.33 tile of a rifle bullet) behind the world. No muzzle flash until feature complete (the user, 2026-11-17).

## Folders inside `react/`

- **One folder per component**, named in kebab-case for its file: `arena-canvas/ArenaCanvas.tsx`. Its children go in its
  `components/` folder, each in a folder of its own, however deep. The tree reads like the screen.
- **`react/components/` splits into `dom/` and `three/`.** A top-level component is `components/dom/<name>/` when it
  renders DOM (HTML, styled with Tailwind) and `components/three/<name>/` when it renders react-three-fiber objects inside
  a `<Canvas>`, so the path says which world it lives in. `react/components/three/arena-canvas/` hosts the `<Canvas>`: it is
  `three/` even though it renders a `<div>`, because it goes straight into a canvas and holds nothing but the minimum DOM
  needed to set it up (the sized wrapper and its `data-ready` hook). Anything else DOM, such as the HUD, is its own `dom/`
  component beside it, never inside it.
- **Below a top-level component, children share its kind, so there is no further split.** Everything under `arena-canvas/`
  is three: `arena-canvas/components/arena-scene/components/bullets/`, flat. A DOM component's children are DOM. If a
  `three/` tree ever needed DOM, that is a new top-level `dom/` component, not a child. Hooks, pure helpers and types are
  not components: they keep the rules below, wherever they sit.
- **A generic hook sits in `react/hooks/<kebab-name>/`** (`use-pressed-key/`: a key that does a thing once, ignoring repeats, with an `enabled` flag; `use-held-keys/`: the keys down right now, read every frame). The user chose this on 2026-11-19 so they are easy to spot; it covers hooks that know nothing of any one component, not every shared hook. B, T, M, R, 1 and 2 use `usePressedKey`; WASD and crouch use `useHeldKeys`.
- **Any other hook sits beneath the thing that calls it**, in `hooks/<kebab-name>/`. `use-game-loop/` belongs to `arena-scene/`,
  and `use-wasd-movement/` beneath `use-game-loop/`, because that is its only caller. A hook two components share rises
  to their nearest common ancestor and no further.
- **Pure helpers go in a subfolder of their caller**, named for their subject (`keys/DirectionFromKeys.ts`), and **every
  type goes in the domain's `types/` folder** (`game/camera/types/Viewport.ts`). A component's own `Props` stays in its file.
  The game loop's own helpers show the shape: `use-game-loop/clock/FixedTicks.ts` is the entry,
  `clock/limits/MaxFrameSeconds.ts` is its helper, and `clock/TickSeconds.ts` stays at the `clock/` root because the hook
  uses it too.
- A component file exports the component and nothing else. A hook file exports the hook.

## Tests

Unit tests are `node`, not jsdom: reducers, clocks and pure functions. A component is covered by an acceptance spec
(`acceptance-tests/`), through the one read-only state hook (`shared/src/state-hook/`), never by a unit test.

`?scenario=cover-hall` (`game/cover-hall/`) is a playtest and spec fixture: a hall one tile wide and ten long with a low cover block at its third and eighth tile, the player and a shooting opponent each in the two tiles behind their own block (a block cannot be walked through, so neither can leave), seven tiles apart on one row, one round, no ring. It is under the arena size limits and its floor is in three stretches, so it is not in the engine's pool and is not validated. The `terraced` scenario preserves its arena and seeded opponent across rounds. `?scenario=mutual-knockout` (`game/mutual-knockout/`) is the duel's first round of a match with no ring or weapon lying about, an unarmed opponent standing six tiles east, and one rifle shot in the air from each fighter at the other, each fighter at the weapon's damage in health, so both fall in the first step and the round is drawn (banner "Draw", score unchanged, "Next round" is the ordinary duel). `?scenario=overlook` (`game/overlook/`) is the terraced arena the other way round: the opponent on the platform at (12.5, 3.5), the player idle on the low ground at (1.5, 3.5), eleven tiles apart; one round, no ring, no match. `?scenario=overwatch` (`game/overwatch/`) is a corridor one tile wide, forty-six long, with a stair at the east end of its low ground up to a platform: the opponent wanders at (30.5, 1.5) and the player stands on the platform at (40.5, 1.5), ten tiles away along the same row, out of the opponent's sight and inside the rifle's reach; one round, no ring, no match. `?scenario=pickup-race` (`game/pickup-race/`) is the duel's arena and fighters in one round with no ring or match, and the submachine gun lying at (17.5, 10.5): four tiles from the opponent, eight from the player. `?scenario=fair-duel` (`game/fair-duel/`) is art's fixture A, the same picture turned half way round, with the fighters at a matching pair of places drawn from the seed (`chooseStartingPlaces`), in one round with a ring and a lying weapon and no score (`nextRoundOfPage` rebuilds the duel, so it is not a match). `?scenario=cover` (`game/cover/CoverWorld`) is open low ground with two low cover blocks (7, 3) and (7, 1), the player at (3.5, 3.5) facing east and three dummies at (8.5, 3.5) standing, (8.5, 1.5) crouched and (8.5, 5.5) crouched in the open; no opponent, ring or match. `ArenaWalls` draws `tile-low-cover` with a flat square fallback. `wallTilesOf` leaves cover out, and a platform still drops to it (`DropsAway`). The read-only snapshot includes opponent level for stair acceptance coverage.
